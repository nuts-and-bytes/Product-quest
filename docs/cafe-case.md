# 蓝山调查 · 3.3

这是把“调查、决策、验证”落实为可操作循环的第一块试验区域。原有章节继续可玩；本次没有批量改写 37 个章节。

## 入口与流程

- 入职第一天到蓝山咖啡馆后，可以喝咖啡、聊天，也可以接下调查。
- 从地图的咖啡馆建筑面板进入，或使用 `?experience=cafe` 直达；直达不会跳过或改写主线。
- 自选调查顺序 → 标记关键材料 → 选择猜测与一项未知 → 组合试验 → 比较后果 → 修改或复盘。
- 8 格行动，首次调查花 1 格，试营业花 2 格。阅读、暂停、整理与离开均不计时；至少保留一次试验机会。
- 单次试验预算为 6 枚，比较另一方案时重新分配。可不收集完整证据直接探索；最多保存四轮试验。
- 两个情境轮换。完成时可选择任何已做过的试验留在店里；下次调查开始时仍保留前一项目的物件。

## 模型边界

`assets/cafe-case-state.js` 是可独立测试的确定性排队模型。每次比较使用同一批 10 位虚构顾客、同样的到达顺序与耐心。点单、制作、取餐分别计算，方案可以影响制作位数量、制作时间、取餐延迟和核单工作。

周三的问题主要发生在出杯之后，周末则主要发生在制作阶段。取餐牌、预点单、借人、精简菜单均有成本或限制，不存在跨情境通吃的方案。拒绝精简菜单的顾客不会占用制作资源；已经下单后放弃等候的咖啡仍可能留在吧台。

“平均停留时间”从进门算到拿走或放弃离开，包含未成交者。店员负担是制作利用率、核单与取餐解释成本的简化估算，不能当作真实经营预测。没有随机抽奖、LLM 评分或隐藏标准答案。复盘同时记录经营后果、当时看过的材料、圈出的依据与尚未验证的假设；后续获得的证据不倒填旧试验。

## 呈现与资源

`cafe-case.js` 管理可访问的 DOM 操作面板；`cafe-case-scene.js` 在现有室内场景中增加物件与三位代表性顾客（第 1、4、8 人）。结果覆盖全部 10 人，画面是抽样重放。手机同时只显示一位顾客的状态标签，减少遮挡。

复用 `PQStory3D`、`PQIsland` 的渲染器、质量调节和动画循环，没有新增 WebGL 上下文、RAF 或联网 AI 调用。关闭调查回收临时角色；退出房间统一回收室内资源。减少动态效果偏好下，重放初始暂停，也可手动播放。

`cafeCase` 独立存入原 JSON 存档，自动跟随导入导出；首次加载旧档时创建调查初态。不会修改 `progress`、`trust` 或 `firstDay` 检查点。读入时校验阶段、证据、预算与试验数量，结果由规则重新计算。

## 验证

```sh
node --test tests/*.test.cjs
node scripts/build-single-html.mjs
python3 -m http.server 8765
```

`tests/cafe-case.test.cjs` 覆盖预算、行动、重复操作、补救、多种组合、情境差异、存档、非法导入与四次探索试验。隔离浏览器测试存档使用 `?player=cafe-qa&experience=cafe`。

这是机制原型。15–20 分钟为设计目标，实际时长、无提示新手完成率、隔天迁移能力和真实手机表现仍需玩家测试。浏览器功能通过不等于已经证明学习效果；下一轮应观察玩家能否解释后果并将判断迁移到周末情境，再决定后续章节改造。
